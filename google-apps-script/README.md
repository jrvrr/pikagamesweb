# Correo de soporte con Google Apps Script

1. Reemplaza el contenido de `Código.gs` del proyecto **pikagames** con [`Code.gs`](./Code.gs). Conserva tu formato `asunto`/`mensaje`/`correo` y la respuesta `success`; esta versión corrige `tucorreo@gmail.com` y comprueba una clave privada.
2. En **Configuración del proyecto → Propiedades de la secuencia de comandos**, crea `SUPPORT_MAIL_SECRET` con el valor de la misma variable en `.env.local`. No publiques ese valor.
3. En **Implementar → Administrar las implementaciones**, edita la implementación web existente, elige una **versión nueva**, **Ejecutar como: yo** y **Quién tiene acceso: cualquier persona** (sin iniciar sesión de Google). Autoriza el acceso a Gmail que solicita `GmailApp`. Conserva la URL `/exec`.
4. En el servidor de producción configura `SUPPORT_MAIL_SCRIPT_URL` con esa URL y `SUPPORT_MAIL_SECRET` con el mismo valor privado. Si editaste la implementación activa y conservaste la URL `/exec`, no cambies las variables de Vercel: la nueva versión de Apps Script entra en vigor sin volver a desplegar Next.js. Si cambiaste `.env.local`, reinicia `next dev`.

Si el formulario devuelve **502** y el servidor registra **401**, la implementación no permite acceso anónimo. Edita la implementación web existente y selecciona **Cualquier persona**; guarda una versión nueva. Abrir la URL con tu sesión de Google no comprueba el acceso desde el servidor.

Los mensajes van a `supportpikagames@gmail.com` y la respuesta usa el correo que el cliente escribe en el formulario. Gmail envía desde la cuenta que ejecuta el script; no puede poner el correo del cliente como remitente. Por eso el formulario usa `replyTo` y muestra ese correo en el mensaje.

El formulario completa automáticamente el correo de quien inició sesión; quienes no han iniciado sesión deben escribirlo. El asunto acepta hasta 30 palabras y el mensaje hasta 50. `probarCorreo()` genera una prueba interna con `ejemplo@correo.com`: para comprobar el correo real del cliente, envía el formulario desde la web. La prueba y el formulario llaman a `enviarCorreo_`, así que usan el mismo HTML y el mismo manejo de Recibidos. Tras cambiar `Code.gs`, guarda y publica una **versión nueva** de la implementación activa; el código nuevo del editor no modifica por sí solo la URL `/exec`.

El diseño HTML se añade con `htmlBody` y mantiene texto plano como respaldo. Cada mensaje tiene un identificador único en el asunto para que Gmail no lo agrupe con conversaciones anteriores. Como el script actual se ejecuta en la misma cuenta de soporte, `GmailApp` coloca el hilo enviado en **Recibidos** y lo marca como no leído. Esta operación requiere el permiso completo de Gmail (`https://mail.google.com/`); si se deniega o falla, el correo se habrá enviado y el fallo quedará en el registro de ejecución. Si más adelante ejecutas el script desde otra cuenta, quita `moveToInbox()` porque movería la copia de esa cuenta, no el buzón de soporte.
